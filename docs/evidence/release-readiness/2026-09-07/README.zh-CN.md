# 2.2.0 发布候选评审

[English](README.md)

这是 2.2.0 候选版本的带日期验证记录，起点为 `39e85125`。评审结束时，修复已提交至候选分支，草稿 PR #57 已创建，三平台候选 CI 已按下文通过；该次评审未执行合并、打标签、正式发布或部署。后续仓库与发布状态不属于这份记录。

## 已修复

- 无鉴权用户定义供应商不再被要求提供 Key，也不会透传客户端凭据。OpenCode 专用身份头仅发送到 Go/Zen，并保留适用的客户端显式值。
- 目录中新增的未知 Zen Free 模型默认使用 Chat，原始名称与去掉 `-free` 的别名均能转发；未保存名称仍在本地拒绝，显式关闭的协议仍保持关闭。
- 账号字段与 Ollama 计费档位在同一事务中提交。注入计费写入失败后，原字段、Key 密文与档位均不变。
- Host 使用密钥打开数据库时，在迁移前检查已有账号密文，当前版本数据库也不再跳过检查。解密失败不会改写数据。
- 桌面初始化在取得单实例所有权后进行。第二次启动不会创建另一份数据，监听端口失败会终止启动。
- Unix CPA 使用现有可执行文件的临时监督模式与生命周期管道，在有界 TERM/KILL 清理完成前保持进程组身份。宿主被强制结束、CPA 提前退出或后代保留输出管道时，不再误用旧进程组编号或无限等待日志线程。
- 前端缓存拒绝过期请求，退出登录使待完成的 Key 请求失效，同进程版本号不会倒退；业务冲突保留真实错误，未修改的设置数组采用远端更新，刷新主 Key 会同步页面显示与复制值。
- 补齐缺失的繁体中文标签及多账号探测提示，修正文档中的旧导航和 Zen 测试预期。最低 Rust 版本对齐锁定依赖的 1.88，并采用编译器给出的等价语法简化，通过严格警告检查。
- Windows 产品改名后的更新会保留旧安装目录，并把新文件写入该目录；已有快捷方式迁移为新名称，旧安装记录仅在原地替换后清理。候选 CI 发现了这一升级缺陷，最终覆盖升级与卸载检查已通过。

Unix 进程所有权经过单独的设计评审，并在实施后接受独立源码检查。整合后的修改与测试证据一并复核。

## 证据边界与评审裁定

- 应用接入测试（包括 Claude Desktop、Gemini CLI）不在该次评审范围内。本报告不提供客户端端到端兼容性证据。随后项目决定整套退役旧应用子系统，见[退役说明](../../../user/applications.zh-CN.md)；旧应用测试不再作为发布门槛，普通 Gateway 协议验证仍属于发布验收。
- macOS/Linux 原生 CI 和 Windows 安装器验收已通过。签名更新分发和真实供应商/OAuth 会话未执行；候选检查不等同于生产签名或分发验证。
- 既有 XOR Key 混淆并非认证加密。解密检查不能识别所有恰好产生合法 UTF-8 的错误密钥；本次未引入加密格式迁移。
- 受评审的面板没有 Applications 导航入口。无鉴权供应商保留文档规定的先删除账号、再删除供应商的非级联流程；删除唯一账号会结束路由，但空供应商仍可删除。重新创建供应商会重建其无鉴权单例。
- 未加入统一的短请求超时，以免打断合法的长时间管理或推理操作。关于 CAS 不会自动更新、整套繁体中文缺失、网关日志翻页的评审推断，经追踪当前实现后排除。
- 依赖漏洞查询因本机 TLS/代理错误未完成，本报告不宣称已完成依赖漏洞审计。

验收使用独立测试数据。临时桌面进程已停止，应用的两项开机启动注册表值已核对并恢复。
