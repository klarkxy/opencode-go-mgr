# Native application connectors

CAS, plaintext Keys, and local model lists: [dashboard API](../../../../docs/maintainer/dashboard-api.md) and [runtime invariants](../../../../docs/maintainer/runtime-invariants.md). Product behavior: [applications](../../../../docs/user/applications.md).

## Implementation hazards

- Keep plaintext Keys on the shortest authorized path: session-protected V3 `GET /connection`, or Core directly to the registered Desktop Host and its fixed client targets. Never place a Key in connector preview/response DTOs, logs, errors, ownership state, sidecars, journals, package source, generated catalogs, package-manager arguments, output, or fingerprints.
- Generate Pi/DSH packages only from checked-in templates, the fixed loopback Gateway URL, and selected public Alias metadata. Pi stores the Key through native provider login. For DSH, field-manage only `OCG_MANAGER_API_KEY` in the selected home `.env`; preserve every other line and restore it on removal. OCG manages only `ocg-manager-pi`, the `ocg-manager-dsh` web-profile bundle, and that one environment assignment. DSH bundle patches replace a matching row's whole config and skip absent ids. Use an `insert` for the OCG companion plugin (fixed route only); never patch `llm-pi-ai` or mount a second copy.
- Invoke only the detected client with fixed argument vectors and a bounded timeout. On Windows, create `.cmd`/`.bat` launchers suspended, place them in a kill-on-close Job Object, then resume; never interpolate a Key or untrusted user text into the command-processor line. On Unix, start the package manager in a fresh process group and terminate the group on timeout. Recheck the client registry and report success only when the exact source was installed or removed (Pi: exact registered OCG source path; DSH: exact digest-named OCG source).
- Generated package sources are immutable direct children of the OCG connector root. Reject symlinks, junctions/reparse points, non-direct descendants, and digest mismatches at every path component.
- Routine tests use temporary homes, temporary data directories, and an injected command runner. They must not discover or mutate real client applications. For manual integration checks, use a dedicated test profile and verify both connect and restore behavior; these checks modify the selected client's configuration. Package-template check: `node --test scripts/application-plugin-packages.test.mjs`.
